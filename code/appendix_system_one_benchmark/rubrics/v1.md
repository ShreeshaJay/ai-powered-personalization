# Reference-Label Rubrics v1

These rubrics are used independently by `claude-opus-5` and
`gpt-5.6-sol`. The judges receive only the `adjudication_input` section of
each manifest row. Sampling strata and weak labels are never shown.

Agreement means exact agreement on every required categorical field. A
disagreement is retained as ambiguous/withheld rather than resolved by one
model overriding the other.

## Product–accessory compatibility

Input:

- Original shopping query for context.
- One concrete anchor product.
- One candidate accessory or companion product.

Judge the directional relationship: “Can the candidate appropriately be used
with this anchor product?”

Labels:

- `incompatible`: Explicit model, size, connector, generation, platform, or
  functional mismatch; or the candidate has no meaningful use with the anchor.
- `insufficient_evidence`: The relationship is plausible, but the supplied
  metadata is insufficient to establish compatibility. Do not guess a fit.
- `generic_compatible`: The candidate is usable with the anchor without a
  model-specific fit requirement, or metadata establishes general
  interoperability.
- `explicit_fit`: Metadata explicitly names the anchor model/family or provides
  matching specifications that establish fit.

Rules:

- Complementarity is not automatically compatibility.
- “Frequently bought together,” category proximity, and the sampling source are
  not compatibility evidence.
- Compatibility is directional.
- Prefer `insufficient_evidence` over unsupported inference.

Required output:

```json
{
  "item_id": "compat_0001",
  "label": "incompatible|insufficient_evidence|generic_compatible|explicit_fit",
  "confidence": "low|medium|high",
  "evidence": ["short factual evidence"],
  "rationale": "one concise sentence"
}
```

## Commerce-query segmentation

Input: one raw query. Return one value for each independent axis.

### Goal

- `known_item_navigation`: Reach a named product, model, title, brand
  storefront, retailer, or website.
- `product_discovery`: Find products satisfying a type, attribute, recipient,
  occasion, or broad need.
- `comparison_decision`: Compare alternatives, seek recommendations, or decide
  what to buy.
- `informational_support`: Learn how something works, troubleshoot, obtain
  instructions, or answer a product-related question.
- `service_account`: Reach an account, login, order, payment, delivery,
  subscription, repair, or customer-service workflow.
- `other_unclear`: Malformed, non-commerce, or insufficiently clear.

### Object

- `product`
- `category`
- `brand_store`
- `service_content`
- `unclear`

### Specificity

- `exact_model_or_identifier`
- `named_product_or_title`
- `product_type_with_constraints`
- `broad_need_or_occasion`
- `none_or_unclear`

### Commerce scope

- `in_scope`
- `out_of_scope`
- `ambiguous`

Required output:

```json
{
  "item_id": "intent_0001",
  "goal": "one goal label",
  "object": "one object label",
  "specificity": "one specificity label",
  "commerce_scope": "in_scope|out_of_scope|ambiguous",
  "confidence": "low|medium|high",
  "rationale": "one concise sentence"
}
```

## Query-to-brand and query-to-category

Input:

- Raw query.
- A randomized bounded list of brand candidates.
- A randomized bounded list of category-path candidates.

The lists always contain explicit escape choices. Do not force a catalog value
when the query does not specify one.

### Brand intent

- `explicit_brand`: The query explicitly names a brand or unmistakable brand
  alias.
- `inferred_product_line`: The query names a proprietary product line whose
  brand can be resolved from common usage.
- `no_brand`: No brand preference is expressed.
- `ambiguous_brand`: A token might be a brand or an ordinary term/name, and the
  query does not resolve it.

`brand_choice` must be one offered candidate ID or `none_or_other`.

### Category

Choose the category path that best captures the requested product type, not a
category for an accessory merely mentioned as context. Use
`other_or_ambiguous` when no candidate is defensible or the query targets
multiple unrelated product types.

Required output:

```json
{
  "item_id": "brand_category_0001",
  "brand_intent": "explicit_brand|inferred_product_line|no_brand|ambiguous_brand",
  "brand_choice": "offered candidate ID or none_or_other",
  "category_choice": "offered candidate ID or other_or_ambiguous",
  "multi_target": false,
  "confidence": "low|medium|high",
  "rationale": "one concise sentence"
}
```

## Judge settings

- Return JSON only.
- Use low reasoning/effort for calibration.
- Do not use tools or external search.
- Do not see the other judge’s answer.
- Do not receive weak labels, candidate provenance, or original ESCI labels.
- Maximum rationale: one sentence.
